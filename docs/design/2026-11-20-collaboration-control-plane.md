# 从聚合面板到可解释的协作控制面

日期：2026-11-20（Asia/Shanghai）。源码基线：公开仓库 main `db0cfad2ac5f7cb4f3f81845698966580f0d3e4d`，beta.14。

状态：本轮设计提案与局部实现；不是新版本发布声明。用户已选定任务优先结构，具体视觉需重设计与独立自审。

## 产品判断

用户需要的是能看清“谁在做什么、为什么受阻、交付了什么、谁对哪个版本验收”的原生协作工作台。
先进程度应由跨机恢复、上下文完整性、证据可追溯和人能否正确决策验证，不能由动画、组件数量或测试总数替代。

现有 DSH 原生 Session、Goal、AgentTeam、Room 和 AgentBus 继续拥有自己的状态与执行语义。
Fusion 负责跨 Host 的能力解释、路由和证据关联，不创建第二套团队调度器或任务权威账本。
保留原生聊天、拖拽缩放与停靠容器；不重建全屏后台，不用遮罩覆盖宿主。

## 当前证据与本轮落实

| 已核实的源码事实 | 对协作的影响 | 本轮处理 |
| --- | --- | --- |
| native decoder 要求 description，但 mapper 丢弃；legacy 有标题时也丢正文 | 接力时缺少目标约束和验收说明 | TaskRecord 增加可选正文，两条 bridge 无损保留 |
| owner、revision、ready、writeScopes、warnings 已投影，但原生详情不展示 | 用户只能看到状态，无法解释阻塞与责任 | 增加只读任务上下文与预期证据展示 |
| 所有本地恢复记录统一裁到 200 条 | 较老的活跃任务可能消失，重启后漏算并发占用 | 全部非终态保留，200 配额只用于终态历史 |
| 默认新入口主要用于观察，旧派发和配置能力尚未全部迁入 | 容易把“可观察”误认为“可执行” | 原生入口已接入显式 allowlisted 作业、单主机派发、回执和签名复核；未把 loopback 结果写成双 Host 通过 |

以上修复保留现有协议和持久化格式。增加可选字段不要求迁移旧记录；恢复记录原有的证据清空与重验规则不变。

## 建议的责任边界

1. **上游权威层**：原生 Session / Goal / Team 持有任务事实、revision 和成员关系。Fusion 只通过受支持接口观察。
2. **观测与投影层**：adapter 归一化正文、owner、依赖、来源序号、来源时间和 freshness。合法空、未知、失败和陈旧必须分开；缺字段不填成 false 或空事实。
3. **意图与能力入口**：继续复用现有 dispatch preview、幂等键和逐动作能力原因。界面先解释目标、限制与所需批准；服务端仍是授权裁定点。
4. **执行与恢复层**：现有 FleetRouter 路由，现有 ledger 恢复执行意图。恢复活跃记录不代表自动重新获得执行授权；网络超时不自动解释为“未执行”。
5. **回执与验收层**：后续把一次执行和一次审查分别关联到精确输入及代码版本。执行回报、证据存在、签名有效与经证明的独立验收是不同事实。
6. **原生体验层**：统一的任务阅读顺序驱动列表、详情和可选海域。视觉层不推断成功，不维护第二份任务真相。

本轮在候选 native panel 落实第 2、4、6 层的受约束切片：Fusion 只保存 attempt、receipt 和 review 关联，派发仍复用 FleetRouter，任务身份与 revision 仍由 DSH 持有。attempt 固定执行节点及材料 pin，派发前有可恢复 reservation；SSH adapter 为单次 attempt 创建隔离 workspace，终态后回读有界材料字节，v2 回执绑定固定 code/input/runtime/config/artifact 摘要与观察事实。签名 review 绑定精确 receipt 与当前任务来源，作业策略撤销节点后旧 review 变为过期。配置公钥签名只证明密钥持有人对指定摘要作出声明；当前 DSH 身份接口不暴露可供此路由验证的稳定 user principal，系统没有证明审核者与执行者身份独立。当前实际运行证据仍只覆盖本机 SSH loopback 合成作业；真实 Host B、生产材料和 reviewer 现场验收仍未完成。

## 后续契约：先定义失败语义，再接执行

| 契约 | 最小字段/语义 | 何时引入 | 新增代价和回退 |
| --- | --- | --- | --- |
| Observation | source、sourceRevision/asOfSeq、observedAt、freshness、原任务引用 | 把不同来源的陈旧程度和兼容原因带到同一面板时 | 兼容旧来源的 unknown；不得虚构时间或序号 |
| ExecutionAttempt | intentId、attemptId、原任务引用/revision、host、输入摘要、状态、时间 | **已实现受限原生纵切片** | 新 attempt 单 worker；已测试同请求幂等、reservation 恢复和不确定状态；真实 Host B 故障/重启矩阵仍待现场验收 |
| ExecutionReceipt | attemptId、执行代码/输入摘要、产物 hash、退出事实、证据引用 | **候选源码已实现材料 v2 回执路径** | adapter 回读材料字节并绑定 pins；只有 loopback 固定文本实际执行，Host B 上的真实 checkout、runtime 和 artifact 仍未验收 |
| ReviewProjection | reviewer 引用、subjectCommit/diffHash、需求版本、证据引用、verdict | **已实现签名复核切片** | Ed25519 绑定任务/attempt/receipt 和当前作业策略；未接入稳定 DSH principal，无法系统证明 reviewer 与 executor/operator 身份独立 |
| WorkspaceLease | workspace/写范围、owner、单调 fencing token、有效期 | 同一工作区确有并发写入且 provider 支持原子校验时 | 每次写入须验证 token；不支持则保持单写者，不把 writeScopes 当锁 |

不为“更先进”增加向量库、知识图谱、新消息总线、新持久任务板或自动自修改器。
需要检索、长期关系或候选补丁闭环时，应先提交对应失败案例、权限边界和可重复评估。

## 三个界面候选

所有候选使用同一组合成 TaskRecord、团队、主机和证据，显著标为 DEMO，零真实执行请求。
周边聊天仅是停靠关系示意，不能作为真实 DSH 宿主验收证据。

| 方向 | 阅读顺序 | 适合的任务 | 取舍 |
| --- | --- | --- | --- |
| 01 横向全景 | 团队概况 → 并列任务/证据 | 同时审查多个协作对象 | 需要较宽停靠区，挤占聊天空间更多 |
| 02 沉浸海域 + 托盘 | 协作意象 → 任务托盘 → 详情 | 偶尔查看团队整体态势 | 意象占比高；动画始终不能代替任务事实 |
| 03 任务优先 | 需关注任务 → 上下文 → 证据；海域按需 | 日常开发、接力和复核 | 建议作为默认，更容易扩展到窄面板 |

推荐 03 作为日常入口，01 作为宽面板视图，02 作为用户主动进入的展示视图。
用户随后确认以 03 的任务优先结构继续，同时否决原稿美感，要求先完成新的视觉设计与独立自审。
当前确认仅覆盖结构，不代表视觉稿已获认可；不替换生产入口或发布新包。

## 评估与升级条件

- 用相同任务对比三方案：找到阻塞原因、负责人、上游版本、预期证据与现有证据；记录误判和步骤。
- 只读链路：正文和空值不丢失、不修改上游输入；负责人信息不推断团队成员关系。
- 恢复链路：旧活跃任务与大量新终态共存；磁盘读回后容量仍拒绝超额派发。
- 预览交互：1440 / 900 / 420 宽度、明暗、搜索空态、详情往返、证据查看、草稿跨方案保留。
- 海域：按需加载、离开时卸载/停止；减动画偏好和渲染失败不阻塞任务阅读。
- 上线前另做真实宿主安装、原生主题/停靠/关闭恢复、真实多 Host 业务、重启/升级矩阵；本地原型截图不覆盖这些门禁。

回退：保持 beta.14 production 不动，修复和预览保留在独立开发分支；无需改真实 profile、部署或凭据。

## 后续最小真实双 Host 纵切片验收（未实现）

以下是后续实现与验收的建议边界，不是本轮交付、运行或通过记录；本轮仍先完成设计自审。
上游继续持有任务真相，Fusion 只关联观察、执行尝试、回执与审查，不新增第二套任务权威账本。

最小路径为：控制 Host A 读取一个上游任务的固定 revision 和输入，经受支持接口向真实 Host B
提交执行意图；B 在独立工作目录内以单写者执行并返回可核对产物；不同于 executor 的 reviewer
审查同一组代码、输入和产物；原生面板分别呈现执行事实、证据完整性与独立审查结论。
不要求第三台 Host，但 reviewer 的身份与审查过程必须独立，不能将 executor 自报通过当作独立验收。
先证明单任务、单写者的闭环与失败路径，不以模拟 Host 或两个本地进程代替真实双 Host。
若允许同一实际工作区并发写入，必须先满足 fencing 门禁；不支持时保持实际可证明的单写者约束。

| 后续门禁 | 不可省的证据与通过判据 | 失败判据与当前尚缺点 |
| --- | --- | --- |
| 1. 来源与授权 | 原任务 ID、revision、正文/要求摘要、来源序号或明确 unknown、观察时间与 freshness；精确目标 Host、动作能力及服务端授权裁定 | 来源失败不得变空集合，恢复记录不得自动续权；Observation 和逐动作判据尚待完整定义 |
| 2. Attempt 身份与幂等 | intentId、attemptId、任务 revision、Host、输入摘要、状态与时间；同 key 同输入重送关联同一已接受尝试，同 key 异输入明确冲突 | 已覆盖 SQLite 原子预留、并发重送、精确 worker ID 与 fingerprint；跨 Host 子尝试和真实进程故障矩阵待验收 |
| 3. 真实跨机执行 | A 的受理记录与 B 的实际开始/退出记录按 attempt 关联；固定代码、配置、命令、运行时身份及实际产物字节 | 代码路径可路由配置 worker，实际证据仍是 loopback；真实 B 上从接受到终态的运行尚未发生 |
| 4. 版本化 Receipt | attempt、执行代码与输入摘要、退出事实、产物 hash、证据引用；经可信 adapter 核对来源，再核对读取到的产物字节 | 候选路径已绑定材料 pin 并由 SSH adapter 有界回读字节；需用 Host B 固定 checkout/runtime/artifact 证明实际运行，不以 loopback 或 exit 0 代替 |
| 5. 独立 Review 与陈旧 | reviewer 身份及独立性、subjectCommit/diffHash、需求版本、输入/产物摘要、receipt 引用、verdict 与时间 | executor 自报不能作独立通过；代码、输入、要求或产物变化后旧结论标陈旧；现有 verdict evidence 投影不等于独立 review 闭环 |
| 6. 恢复与不确定性 | 在发送、远端开始、回执到达、落盘等断点重启后，仍能找回同 attempt、保留占用并重新核对 | 派发前 reservation 可用同请求恢复；标记为可能已发送后不自动重派。远端运行中断、完成后回执丢失、ledger 损坏及 Host B 重启仍须验收 |
| 7. 写入隔离 | 最小版证明独立工作目录与实际单写者；共享写入时由接收端对每次受保护写入原子校验单调 fencing token | 覆盖旧 worker 复活、过期 token 与网络分区；writeScopes 不是锁，跨机 fencing 尚未实现 |
| 8. 原生闭环呈现 | 在真实 DSH 中从任务定位本 attempt、receipt 与 review；420px 可读、返回身份不变，三种事实各有状态与来源 | 缺证据、任务移除、陈旧审查及来源失效不得变成功；独立稿和合成容器不能代替真实宿主验收 |

接执行前还须明确四类判据：Attempt 的超时/显式重试规则；任务 revision、需求、输入、代码与产物的
绑定和失效范围；Receipt 来源信任及 reviewer 独立性；稳定身份、占用、证据与审查的持久化或重验规则。
真实执行须另获对应环境和动作授权，并按精确版本记录证据；此小节本身不授权远端执行、部署或生产变更。
