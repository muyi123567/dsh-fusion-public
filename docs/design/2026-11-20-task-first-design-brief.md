# 任务优先：原生工作面的视觉重设计

日期：2026-11-20（Asia/Shanghai）。状态：静态方向获用户初步认可；快速展示动画增量已通过本轮自审，尚未接入原生生产入口。

## 已确定的任务

用户选定第三版“任务优先”的结构，并明确否决旧稿的美感，要求先认真设计、通过独立自审，再继续原生接入与真实多机闭环。
本轮交付一套有明确视觉取舍、能在真实面板宽度下阅读的设计稿；结构不重新比选。

上轮已完成的正文投影、恢复修复与测试保留。本轮不把视觉稿当成真实多机执行、版本回执或独立验收已经交付。

## 旧稿为什么被否决

- 顶部方案、来源、品牌、工作台、面包屑和副标题叠加，420px 截图中第一条任务约在 y=354 才出现。
- 大面积相邻灰绿底色、低对比小字与细边线混在一起，没有清晰的视觉重心。
- 任务名、负责人、时间、证据数量和说明几乎同权；风险只剩很小的彩色标签。
- 详情先呈现许多属性，当前事实、下一步和证据出现得太晚。
- 反复的 Waves 图标与三层“工作台”命名没有形成产品识别，反而增加噪声。

## 视觉方向：航次日志

像一份编排清楚的协作记录：暖白纸面、清晰墨色、少量海色；通过字阶、对齐和留白建立美感。
不靠大阴影、大圆角、彩色卡片或默认展开的海景建立“高级感”。

- 浅色：暖白 `#FBFAF6` 主面、墨色 `#1D2931` 文字、海色 `#14767D` 少量强调；辅助色 `#606D74` 在选中与证据底色上保留可读对比。
- 深色：中性炭黑 `#111315` 背景、`#191C20` 面板、`#F0F1EC` 主文字、`#A8B0B6` 次级文字、`#7CC8C1` 海色。
- 预览字体：Inter / Noto Sans CJK SC / system sans；未来原生接入必须继承宿主字体与语义色。
- 字阶：任务名 15–16px、详情标题 24px、正文 14px/1.7、辅助 12–13px；中文不设负字距。
- 以 8px 间距节奏组织段落；边线只用于必要分组，主体不嵌套成卡片。
- 品牌只出现一次，普通属性不装饰小图标；状态与证据类型使用现有图标库。

## 内容与交互顺序

列表：紧凑全局来源/团队上下文 → 搜索筛选 → 需要关注 → 进行中/稍后。
失败、受阻、待验收均有文字事实；已回报完成主动降权。选中态不比风险事实更强。

详情：常驻返回与来源（窄面板）→ 任务编号与来源原状态 → 任务名 → 当前事实/缺口 → 阅读证据 → 简明归属 → 来源证据 → 折叠的完整任务正文。
上游 ready、写范围提示、执行结果与独立验收分别解释。

原型只展示现有 TaskRecord 与证据可表达的事实。未来版本绑定回执只能明确写“尚未接入”，不画成完成链路，不提供假运行/批准按钮。

## 原生容器约束

- 插件只拥有 DSH 右栏正文；标签、关闭、拖拽、宽度和中央聊天归宿主管理。
- 审稿工具中的主题/宽度控制与聊天必须标明外围示意，不能成为将来插件正文的一部分。
- 420 / 560px 为单栏列表→同面板详情；约 800px 以上的宽容器才采用约 300px 列表与详情并排。
- 响应依据容器宽度，不以浏览器视口宽度冒充原生面板宽度。
- 420px 正文顶部至第一条任务不超过约 130px；宿主/审稿外层另行计量。
- 面板高度由宿主分配；低高度仍保留返回、搜索与滚动阅读路径。

## 自审要求

必须查看新鲜的宽面板整体、420 列表、420 详情、560px、深浅主题截图。
同时检查 100% 尺寸的中文、长标题/ID、合法空集、来源陈旧、键盘返回与焦点。

以下任一问题未解决即不通过：

1. 第一眼仍落在元说明、品牌大标题或海域，而不是任务与当前事实。
2. 420px 被多层标题占满，或需要缩小关键文字才能排下。
3. 灰度与轻度模糊后仍看不出主次；所有行/矩形等权。
4. 风险只靠颜色区分，或者大面积选中底色压过风险事实。
5. 正文/关键原因小于 14px，辅助文字对比不足以正常阅读。
6. 仍是旧稿换色加装饰，没有改变任务行与详情的阅读顺序。
7. 未交付能力被画成已运行，或预览控制混入原生正文。

审查要区分可测的布局/可读性问题与主观审美判断。自审通过只表示可提交用户评审，不代表用户已认可，也不代表真实宿主验收。
