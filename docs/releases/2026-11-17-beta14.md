## 当前产品

鲸从 DSH 侧栏入口或右栏添加页打开原生右侧面板，默认显示任务。
任务、主机、团队使用紧凑列表，点击记录在同一面板内查看详情，并提供返回与面板内 Escape。
标签、关闭和宽度由宿主管理，颜色与字体继承 DSH 主题。
本 native 候选默认用于任务 / 主机 / 团队 / 海域查看与证据导航。旧 FusionApp 的派发、
配置、运行与终端组件及 host API 保留在源码中，尚未全部迁入新入口，
不能将本版 UI 描述为与 beta.13 完全等价。既有[公开任务视图扩展契约](../extensions/task-views.md)
继续保留，接入对象是任务集合视图，不是单条任务详情；生命周期恢复的增量验证见下文。
桌面采用宿主右栏布局；窄屏下宿主可能自行切换全屏，这属于 DSH 的响应式行为。

海域是用户主动选择的可选视图，按需加载界面与 3D 模块。
鲸群、子代理与任务意象仅投影已经观测到的数据；面板不创建新的调度或验收权威状态。
当前快照是 Fusion 全局来源，不声称是当前 DSH 会话的专属任务。
团队成员以 `AgentTeam.taskIds` 的显式声明为准。

任务状态、进度和证据分别显示；缺少证据不等于成功，任务完成也不等于独立验收通过。
主机连接、兼容性、能力声明与权限分别解释；SSH 可达不等于 PTY 已登录或任务完成。
可选团队来源缺失、读取失败、陈旧快照与合法空数据应分别解释。
主机来源不可用与合法空板的区分已在 `e9f3910` 实现，并在当前包的真实来源检查中通过，
与显式 DEMO 扩展 / 场景数据分别验收。

## 安装与 beta.13 → beta.14 升级

需要 Node.js `>=24.9.0`；DSH 安装范围为 `>=0.2.0-rc.2 <0.3.0`。
beta.14 的 recommended / tested 仅为 `0.2.2-rc.3`，candidates 为
`0.2.0-rc.2`、`0.2.2-rc.1`；安装范围不变，安装允许不等于实测通过。
rc.3 的 verified 仅依据 beta.14 隔离启动与原生 UI 的已测范围，不覆盖真实模型或多机业务。
新客户端使用 `commandTarget`、`openTab` 与 `tab.visible`；已核对的旧宿主也有所需 API，
不将其标为 unsupported。`0.2.2-rc.1` 的历史 verified 属于旧包，
beta.14 与旧宿主的运行组合尚未重新实测，不能沿用 beta.13 的 UI 结论。
维护者已统一更新兼容元数据；变更后的完整源码 suite、原生 / 插件 / package 契约已通过。
当前候选的三组实际运行已完成；历史包 UI 记录仍分别保留，不代替当前包的范围说明。
原生面板还要求宿主提供右栏能力；缺少能力或未选择会话时，界面会提示。

1. 下载维护者提供的 beta.14 tarball 与对应 `SHA256SUMS`，确认校验值属于同一最终包。
2. 备份要升级的 profile 的 `package.json`、锁文件、Cordis 用户配置和 Fusion 自有状态；保留 beta.13 tarball。
3. 通过 DSH 宿主安装候选包，示例 profile 为 `web`：

   ~~~sh
   dsh plugin --profile web add ./dsh-fusion-0.2.0-beta.14.tgz
   ~~~

4. 重载对应 profile，选择会话，从侧栏「鲸」或右栏添加页打开面板。
   新建隔离 profile 若出现上游预览版确认或可选模型引导，按宿主流程确认并跳过模型配置；不需要开启模型或发送消息。
5. 在有授权的隔离 profile 复验任务、详情返回与实际来源。
   需要回滚时，通过宿主安装保留的 beta.13 包并重载；状态恢复使用升级前备份。

不通过手工覆盖 `node_modules` 完成升级。companion 安装与校验沿用
[插件说明](../../packages/plugin/README.md)，无需为查看面板开启模型写入或远程终端。
本轮安装与验证仅针对授权的隔离环境；未改动用户 production profile、生产配置或真实运行任务。

## 已知限制

任务状态投影最多覆盖 600 条记录。原生任务列表仍使用完整原始快照，不因该投影上限裁剪；
但超出投影范围的任务可能缺少由依赖推导的受阻标记，因而不保证享有相同的依赖优先排序。
缺少投影标记不能解释为依赖已解除或任务已成功。
